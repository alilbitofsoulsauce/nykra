# v0.26 — Nykra adaptive versus depth baseline on external issue #1134

## Result

**Tie: both arms solved 1/1 issue, in one shared model proposal. No adaptive-policy advantage was observed.**

The benchmark is a real historical **feature request**, not a newly discovered bug:
[more-itertools issue #1134](https://github.com/more-itertools/more-itertools/issues/1134),
implemented upstream in commit `18c57c720fc5a7672439ea45a5393a8c1ff40d1e`.
The buggy/feature-absent revision is its parent,
`9210d54527ddfa63ebe75cd5b5daa0201902c674`.

| Objective | Depth baseline | Nykra adaptive |
| --- | ---: | ---: |
| Attempt cap | 4 | 4 |
| Agent-authored proposals evaluated | 1 | 1 |
| Public test cases | **6/6** | **6/6** |
| Withheld test cases | **10/10** | **10/10** |
| Original source modules changed | 2 | 2 |
| Selected patch SHA-256 | Same in both | Same in both |
| Controller decision changed | No | No |
| Fully solved on frozen tests | **Yes** | **Yes** |

The identical first patch was tested twice, once under depth and once under
adaptive, by the same Nykra restricted Git/Docker patch evaluator.
The model-authored proposal was produced **once by GPT-6 in this supervised
ChatGPT conversation**. It was *not* separately generated by independent model
sessions. Consequently there was no substantive alternative model output and
no opportunity for Nykra's adaptive strategy to improve a branch decision.

## Protocol and preflight

Before submitting a patch, the supervisor froze a six-case public suite and
a separate ten-case withheld suite, verified the historical upstream
revision and its fixed reference, and selected the exact same attempt budget
and evaluator for both arms. The reference passed both suites; the original
upstream revision failed both.

- Public and withheld suites are archived, including exact SHA-256 hashes, in
  the [machine-readable protocol](evidence/v26_external_moreitertools_1134_protocol.json).
- Public grading used pinned Python 3.13 Docker, no network, a read-only
  checkout, non-root user, dropped capabilities and bounded CPU/memory/process
  limits. This is not a certified hostile-code sandbox.
- The verifier did not disclose withheld cases or outcomes to the proposal
  source during either arm.
- The selected complete two-file Git diff is archived as the
  [single shared model patch](evidence/v26_external_moreitertools_1134_model_patch.diff).
- Git source history in the submitted candidate workspace contained **only
  the feature-absent snapshot**, not the upstream fixed commit or diff.

Two *advertised-free* OpenCode model connectivity attempts,
`opencode/mimo-v2.6-flash-free` and `opencode/ling-3.1-flash-free`,
timed out without returning even a readiness token. No paid inference was
automatically invoked. The initial protocol and the **pre-proposal provider
amendment** are preserved separately. This is not a same-model, independent
inference trial.

The original upstream Python blobs had CRLF line endings, whereas Nykra's
Git patch validator rejects CRLF patch input. Before either arm was scored,
both target source files were normalized **only from CRLF to LF**, and the
normalized benchmark starting point was committed. Both arms used the exact
same normalized Git SHA; public/withheld tests and semantic source content
remained unchanged. Exact original and normalized content hashes and the
revised Git SHA are in the protocol. The original upstream SHA is retained.

## Independent grading and negative results

The independent final grading applied the selected patch to a fresh
disposable checkout per arm and ran ten withheld cases in Docker.
Both passed **10/10**. Upstream reference preflight also passed those ten.

For additional compatibility, the patch passed four existing upstream
running-mean/median unittest methods. The upstream reference passed five
because its newer historical test file contains one additional method.
This is not a same-size comparison and is reported only as a compatibility
check.

A wider `tests.test_more tests.test_recipes` execution ran **867 tests**
but **did not pass**: the restricted Docker configuration reported one
failure and three errors (five skipped), including an unrelated
`callback_iter` doctest that could not create a thread under its
64-process cap. The cause of *every* broad-suite failure was **not**
independently established, so **a clean full-upstream-regression result is
not claimed**. The nonzero result is retained in
[the raw regression record](evidence/v26_external_moreitertools_1134_upstream_regression.json).

Public evaluation times also differed substantially between cold and warm
Docker starts. They are **not** valid model-speed comparisons, and no
timing or token-efficiency uplift is claimed.

## Evidence and what this does not prove

The [full machine-readable summary](evidence/v26_external_moreitertools_1134_summary.json),
[arm attempt receipts](evidence/v26_external_moreitertools_1134_arm_receipts.json),
[public/reference preflight](evidence/v26_external_moreitertools_1134_preflight.json),
and [immutable candidate diff](evidence/v26_external_moreitertools_1134_model_patch.diff)
record all successful and failed checks.

**The outcome is a tie.** Both arms share a single ChatGPT model output,
with one issue, one proposal, no diverging controller decision, and the
same hidden result. There is no causal evidence that adaptive exploration
improves coding accuracy; one task cannot estimate general advantage.
This task was historical, so training contamination is unknown.
The public/withheld test sets were frozen by the supervising assistant,
not a third-party blind grader. This is not an official SWE-bench or
BugsInPy leaderboard score.

A future serious comparative trial needs two actual independent model
sessions under the same provider and budget, several previously unused
external issues, preregistered held-out tests, and an exercised controller
fork. Preserve failures and exclusions rather than filtering them.
